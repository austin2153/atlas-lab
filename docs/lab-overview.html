Atlas Lab

A single Proxmox server running a two-node Talos Linux Kubernetes cluster. Terraform builds it, and everything on top is deployed with GitOps. I use it to practice platform engineering and Ansible/VMware automation.

Topology

The gateway routes between three VLANs. Proxmox gets a trunk port, and each guest is tagged onto its VLAN at the bridge.

Network

UniFi handles routing, Wi-Fi and DHCP. Pi-hole is the DNS server and holds every *.atlas.local record.

How it gets built

  1. Terraform creates the cluster

    The bpg/proxmox and siderolabs/talos providers download the Talos ISO, create both VMs on VLAN 20, apply the machine configs and bootstrap etcd. State lives in Terraform Cloud, but runs execute locally so they can reach the private network.

  2. ArgoCD installs the platform

    One root ApplicationSet watches platform/. To add a service, I add a folder and push to main. It's live within a few minutes, with self-heal and prune enabled.

  3. Kratix and Flux handle self-service requests

    A request such as "give me a Proxmox VM" goes through a Kratix promise pipeline. The pipeline writes manifests to state/ in Git, and Flux applies them to the cluster.

Lessons learned

  • Keep databases off local-path volumes.AWX's in-cluster Postgres lost its data twice after power cuts. It now runs in its own LXC on ZFS.
  • Talos is read-only.local-path-provisioner had to move to /var, and its namespace needed privileged PodSecurity.
  • Pinned MAC addresses make rebuilds painless.Each node keeps its MAC and IP across a full destroy and rebuild.
